# Bebop-vision project dependencies — ONE venv for the whole project.
#
# Target: Jetson AGX Thor, JetPack 7.2 / L4T 39.2, CUDA 13.2, Python 3.12.
# The recorder/perception/places stack AND the voice stack (TensorRT
# Edge-LLM: the ASR -> brain -> TTS cascade, or Qwen3-Omni) share
# `bebop-vision/.venv`.
#
# The venv is created with --system-site-packages so JetPack's TensorRT
# Python bindings (system dist-packages) are visible to the voice stack.
#
# Pinning policy: pin ONLY where a specific version is required — a CUDA
# build, a vendor ABI, an engine format. Everything else is a floor, and
# transitive dependencies are not repeated here.
#
# Do NOT pin system-provided packages here (tensorrt, Jetson.GPIO, PyGObject,
# ...): --system-site-packages already exposes them, and pinning would try to
# fetch them from PyPI.
#
# Bootstrap (from bebop-vision/), also done by
# `scripts/install-jetson.sh --setup-voice`:
#   1. python3 -m venv --system-site-packages .venv
#   2. .venv/bin/pip install --upgrade pip
#   3. .venv/bin/pip install --extra-index-url https://download.pytorch.org/whl/cu132 \
#        'torch==2.13.0+cu132' 'torchvision==0.28.0+cu132'
#   4. .venv/bin/pip install -e . --no-deps      # registers the package only
#   5. .venv/bin/pip install -r requirements.txt
#   6. .venv/bin/pip install --no-deps 'pyorbbecsdk2==2.1.2'   # see below
#
# `requirements.lock.txt` is the exact verified set (generated on the robot).
# `--setup-voice` installs it in preference to the floors below, so a rebuilt
# venv reproduces the deployed robot.

# --- ABI-critical: venv-local numpy-2 builds must shadow the system --------
# JetPack ships numpy 1.x in dist-packages, so a venv-local numpy 2 (with a
# scipy/pandas built against it) has to win. scipy matters because
# transformers does an optional `from scipy.optimize import ...` that would
# otherwise resolve to the system scipy and die on `from numpy import Inf`.
# pandas is needed by the NVFP4 quantizer (modelopt) for the same reason.
numpy>=2
scipy>=1.14
pandas>=2.2

# --- torch -----------------------------------------------------------------
# Pinned: the cu132 aarch64 build is mandatory (PyPI's aarch64 torch is
# CPU-only), and torchvision must match torch's minor version exactly.
torch==2.13.0+cu132
torchvision==0.28.0+cu132

# --- perception / recording / places -------------------------------------
transformers>=5.14
opencv-python>=4.10
mcap>=1.4
protobuf>=4.25
PyYAML>=6
huggingface_hub>=0.26
websockets>=12

# --- ONNX Runtime (CUDA EP) -----------------------------------------------
# The reference for checking engines built on the Thor against their ONNX
# export (docs/path-model.md); nothing in the tree imports it today. Pinned:
# the CUDA-EP build must match the platform's CUDA 13. Never install plain
# `onnxruntime` alongside it — they share the import name. `onnx` itself
# comes with tensorrt-edgellm[tools] below.
onnxruntime-gpu==1.29.0

# --- voice (TensorRT Edge-LLM) --------------------------------------------
# Pinned exactly: the compiled engines AND the `edge_serve.py` compatibility
# patch are specific to this build. The aarch64 wheel covers Jetson Thor
# (JetPack 7.x, CUDA 13, SM110, platform TensorRT 10). `server-tools` pulls
# the Transformers the checkpoint-direct builder needs; `tools` pulls the
# NVFP4 quantization toolchain.
tensorrt-edgellm[server,server-tools,tools]==0.11.0
httpx>=0.27

# --- dev / test -----------------------------------------------------------
pytest>=8

# ===========================================================================
# Deliberately NOT listed here
# ===========================================================================
#
# pyorbbecsdk2  — the Orbbec camera SDK. It is a real runtime dependency, but
#   it cannot live in this file: it hard-pins `av==12.3.0` (py<3.13) while
#   `tensorrt-edgellm[server]` hard-pins `av==17.1.0`. No single av satisfies
#   both, so any resolution containing both is impossible. We use the SDK for
#   *capture* only (its av-based recording helpers are unused), so the camera
#   works fine on av 17.1.0. Install it with `--no-deps` (step 6 above).
#   Consequence: `pip check` always reports that one conflict. It is expected
#   and harmless — do not chase it.
#
# av (PyAV)     — not pinned here because `tensorrt-edgellm[server]` already
#   requires (and pins) it. Pinning something newer breaks the resolution
#   above; it is also unused by our runtime code (the recorder encodes through
#   GStreamer/nvv4l2 — bebop_vision/hw_video.py), and only the offline tools
#   under tools/ import it.
#
# tokenizers, safetensors — pulled by transformers itself.
