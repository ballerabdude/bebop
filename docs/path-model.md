# Path model — learned path prediction and following (proposal)

Status: **proposal, 2026-10-22/23; the path model, the follower and the safety envelope are not implemented** (groundwork that landed since is listed below). Written to answer "how do we run a fixed-rate
model that predicts the robot's path from vision and have the robot follow it, given that the
near depth camera misses low floor items (dolls, clothes)?". Produced by a research / design /
adversarial-verification pass over the visual-navigation literature, driving-policy practice and this
repo, plus prototype measurements on the six 2026-10-18 recordings (scripts and previews under
`bebop-vision/datasets/bev-student/hindsight-prototype/`, gitignored). One tick model
(traversability + timed path), intent/keyframe goals, guarded pure pursuit. Tags: (M) measured, (P) predicted from a measured anchor, (T) target, (R) read in the repo today. Four findings changed the design itself: the near camera sits at -59.5 deg, not the YAML's -66; the obstacle grid must be anchored in the gyro-fused frame and scrolled by whole cells; zeros streamed in HOLD defeated human takeover in the firmware of the time (since changed, below); the twist client needs a latest-wins slot with Acks, not a 64-deep FIFO.

## 0. TL;DR
- One model, two TensorRT engines, in `bebop-vision/main.py` on a 100 ms timer that takes the newest paired frame set: a DINOv3 ViT-S/16 over the near floor crop (1280x460 resampled 1.5x to 848x304), the far frame (416x256) and a cached subgoal keyframe emits a stride-4 traversability mask and a 3 s body-frame path (K=3 hypotheses x 16 timed points (x, y, psi, v) with Laplace scales, a stop logit, a distance-to-goal).
- The mask is lifted at the calibrated pitch (M: -59.5 deg / 1.263 m) into a 5 cm grid anchored in the gyro-fused frame F and scrolled by whole cells; cells hold until re-observed. The grid is the only rule that touches the path: it selects, slows or stops.
- Labels are hindsight (odom distance + camera-gyro heading, stuck/slip flagged): swept-footprint positives, SAM 3.1 negatives mainly from holes in its floor mask (M: the 'sock' and 'doll' prompts return nothing); negatives win, conflicts go to the user.
- Goals: v1 is intent-conditioned (keep / left / right / stop from the operator, or from the VLM at a decision point; goal image masked); v1.5 adds goal keyframes built from the recordings as A->B edge tracks, which is also the first live test of the untested `place_edges` graph. 50 Hz pure pursuit with 0.375 s pose prediction, yaw closed on the gyro; v1 capped at 0.3 m/s in Python and 0.35 m/s in firmware; no reverse.
- Nothing moves without a go (`POST /nav/go`, checklist, 2 s heartbeat); a stop is a 0.6 s burst of zeros, never a stream. Week 1 is measurement plus a firmware preemption/cap PR; first twist, with a go, in week 6.

## 1. Design principles
A frame-locked tick: one model pass per camera frame set at a fixed rate, stamped with the frame it saw. A timed plan in position space with a speed channel and per-point uncertainty scales, rather than raw wheel commands, so the controller and the actuator lags stay outside the model. Hindsight labels: the robot's own future trajectory, posed into the frame it was looking from, is the supervision, so every recorded tick is a label. An intent input resolves multimodality at junctions instead of asking the model to guess. The model plans; a separate controller tracks the plan at a higher rate, re-anchors it between ticks with dead reckoning, and soft-disables on a stale plan. Not adopted: a 20 Hz tick (the yaw plant has a 0.30 s lag after a 0.075 s delay, and GPU power is the budget), long horizons (a 3 s path already spans the near camera's view at these speeds), lane or lead-vehicle structure, a learned simulator, and a link-independent takeover path, which this robot does not have yet.

## 2. The loop
`NavPolicyService(rig, hz=10, video_server=vserver)` lives in `main.py`, which owns the cameras, follows the pattern of the removed `BevService` (a threaded 10 Hz tick over the rig with start/stop/latest/status and a video-server publish; `git show 1f22b61:bebop-vision/bebop_vision/bev_service.py`), is `tracked` in `bebop-models` and sits behind `--path-policy` (default off). Gate: frame age p95 <= 60 ms, rate 9.5-10.5 Hz, pair skew p95 <= 5 ms.
Latency image -> twist is 50-130 ms median (E; nvjpeg decode unverified, the measured 35 ms CPU path is the fallback; inference 7-12 ms median / 15-30 p99 (P)), then actuation 0.05 + 0.08 s (v) and 0.075 + 0.30 s (omega); each plan logs camera stamp, t_pre, t_infer, t_pub and t_send.
Power (M): the 10 Hz BEV student (23 ms GPU + 35-42 ms CPU decode) moved VDD_GPU 4.7-7.1 -> 9.5-10.7 W and VDD_CPU_SOC 6.7-7.1 -> 7.9 W, a 3-7 W delta with no averaging window recorded; PathNet-S has the same decode and at least the same GPU work: (P) 3-6 W. Gate: <= 6 W as the difference of >= 5-minute means of VDD_GPU + VDD_CPU_SOC, on vs off, same nvpmodel/jetson_clocks state, under the recorder, four WHEP viewers, the scout, the `nav` overlay encoder and whatever `vision.env` starts.

## 3. The path model (PathNet-S)
Inputs: the near crop, fixed after K0 as rows `[r_top, r_crossbar]` (crossbar rows ~425-445, floor 0.62-0.67 m; `r_top` the ~2.0 m row), resampled anisotropically to 848x304 = 1,007 tokens so the benchmarked shape is the trained shape; far 416x256 = 416 tokens; the goal keyframe 416x256, encoded once per subgoal and cached; history = 16 near + 8 far pooled tokens per past tick at t-0.2 .. t-1.0 s with a Delta-pose; grid tokens = the central 60x60 window of the section 5 grid, 6x6 cells per token -> 100 x 5 channels (log-odds, unknown, tall, drop, age); a 24-float scalar token (v_odom, omega_gyro, last twist, actuation offsets [0.15, 0.45] s (the times ahead at which the plan is queried), t_since_switch, goal-mask bit, intent one-hot, hops).
Backbone: DINOv3 ViT-S/16 (`facebook/dinov3-vits16-pretrain-lvd1689m`, gated; the checkpoint sits in the gitignored `bebop-vision/weights/dinov3-vits16/` on the workstation, loaded with `AutoModel.from_pretrained`; the loader and FPN of the BEV student removed on 2026-10-23 are at `git show 1f22b61:bebop-vision/bebop_vision/bev_student.py`; the places service's `DinoV3Encoder` is ViT-L/16 and is not this backbone), shared by near/far/goal, LayerNorms + last 4 blocks trainable. The removed student's FPN was bilinearly upsampled stride-16 tokens (8x6 cm of floor per token at 1.0 m), so the mask head gets a <= 128-channel stride-4 conv stem on the near crop fused with the tokens, plus an 8-d reconstruction bottleneck on traversed patches (anomaly -> `unknown`).
Tensor contract (fp16, static, TensorRT 10.16.2): `pathnet_backbone`: `near [1,3,304,848]`, `far [1,3,256,416]`, `goal [1,3,256,416]` -> `near_tokens [1,1007,384]`, `far_tokens [1,416,384]`, `goal_tokens [1,416,384]`, `near_stem [1,128,76,212]`; `pathnet_head`: those + `hist_tokens [1,120,384]`, `hist_dpose [1,5,3]`, `grid_tokens [1,100,180]`, `scalar [1,24]` -> `plan [1,3,16,8]` (x, y, psi, v + four scales), `mode_logits [1,3]`, `stop_logit [1]`, `dist_s [1]`, `arrival_logit [1]`, `mask [1,2,76,212]` (traversable logit, anomaly; pixel (i,j) covers crop rows 4i..4i+3, columns 4j..4j+3), `recon_err [1,76,212]`. Parity: fp32 vs fp16 within 1 cm / 1 deg, mask IoU >= 0.99.
Latency (P): 95.5 GFLOP by FlopCounterMode; anchored to the student (49.2 GFLOP = 2.39 ms trtexec, 3.75/8.76 ms p50/p99 live): 5-9 ms trtexec, 7-12 ms live median, p99 15-30 ms. Kill at median > 30 ms or > 8 W: shrink far/goal to 320x192, then rate, never the near crop.

## 4. Labels from the existing MCAPs
Calibration first (K0): three fits put the near camera at ~-59.5 deg (gravity 58.8-59.1 deg; 48 RANSAC floor planes median -59.5, height 1.254-1.277 m; principal-point floor depth 1.46 m vs 1.39 m at -66) and the far at ~-8.6 deg (gravity 8.5-8.7; horizon row 305, not 215). Re-checked independently from the still-period accelerometer means of session 193932: near -59.1 deg, far -8.7 deg, i.e. 7.0 deg and 8.8 deg of residual tilt against `config/orbbec_rig.yaml` (-66 / -17.4, measured 2026-09). Anything that lifts with the YAML mount (the BEV student's LUT, removed with it on 2026-10-23, and the removed stop-cone geometry) has been 14-22 cm short at 0.5-1.2 m; the SAM label pipeline fits its own floor plane per frame and was not affected. Verify on the physical rig before editing the YAML, then record the method (accelerometer at rest) so it can be repeated after any remount.
Heading: the near gyro's yaw rate (third row of `mount_rotation(pitch_meas, 0)`), bias from still periods, integrated on device dt, far gyro as cross-check (M: 3 s agreement p99 1.0-2.0 deg, lateral p99 <= 1.1 cm); a 1-2 % common-mode scale error (4.7-9.4 cm at 3 m) needs the taped course. Odom heading is rejected (M): > 10 deg off at +3 s in 5.5-6.3 % of gap-free moving windows, 2-3.5x over-read in slow carpet turns, -57 deg of phantom rotation while blocked.
Recorder stalls (2-18 per session, 0.5-1.2 s) drop odom, frames and gyro together: 10.9-11.9 % of 3 s windows have no gyro path and leave the path loss until the recorder fix (`recorder_mcap._drain_imu`) lands.
Traversability: positives = `config/ego_mask.npz` swept over +0.5 .. +3 s and projected at the calibrated pitch; weak positives (0.3) = SAM floor minus objects; negatives, which win every conflict = SAM 3.1 wall/furniture/obstacle masks, holes in the SAM floor mask (the main low-clutter channel), the low-clutter prompts where they fire, `person` dilated 0.3 m, depth >= 10 cm above the plane. K2 partial (M, 28 clutter frames, SAM 3.1 at 0.5 (its hard-coded processor threshold at the time; `--conf` became effective on 2026-10-23)): object prompts mask large or colourful items but 0 of 14 small or dark ones; the floor mask leaves a hole around 12 of those 14 and absorbs 2 (a dark blanket on carpet, a tan mat); a thin cable on carpet is caught in 70-80 % of frames.
Reverse windows (M: 19-31 % of 3 s windows contain a reverse step; 44-55 % in sessions 191941 and 193932): a window whose future contains a backward step (odom forward step < -1 cm or cmd vx < 0) is a recorded course correction, not a path to imitate. The path label is truncated at the first backward step and keeps the approach-and-stop that precedes it (stop supervision); frames during the reverse are excluded as inputs (the forward cameras do not see where the robot goes, and v1 never reverses); the forward frames after the reverse are tagged recovery starts and weighted up; footprint positives come only from the forward part of the sweep. The label heading is the gyro, so the castor yaw of a reverse from standstill does not corrupt the paths before or after it. Census per session in the label report.
Augmentation: photometric and JPEG jitter, flips with mirrored labels, and recovery perturbations on 30 % of samples by the exact flat-floor homography of the near crop (lateral +-0.3 m, yaw +-10 deg, pitch +-1.5 deg) with a quintic rejoin and an identity warp on every sample; planner-relabelled clutter (section 5).

## 5. Low floor obstacles
The near camera (1.26 m, -59.5 deg) looks down on low objects, so the top surface carries the signal: at 1.5x a 3 cm face is 2.4-5.2 px at 0.3-1.2 m, a 2 cm sock face ~3.1 px at 1 m, flat cloth 1-2 px, a 10 cm top ~25 px across at 1 m. Depth cannot: a 3-5 cm plane tolerance is 32-72 mm of along-ray depth and the doll registered only at 0.32 m.
Supervision: exclusion (a sock is a hole in SAM's floor mask); hand masks on the static set for what SAM absorbs; the reconstruction bottleneck (never-seen objects are `unknown`, cost 0.5); copy-paste of static-set cut-outs at IPM-exact scale; planner relabelling: a pasted object crossing the hindsight ribbon becomes a grid detour with >= 0.15 m clearance only if the fitted plant can execute it, else a stop.
Grid: per-pixel probabilities -> a 5 cm grid through the calibrated homography, in the fused frame F (odom distance + gyro heading), never `odom_theta`: 80x80 cells, recentred by whole cells whenever the robot leaves the central 0.5 m, never rotated or resampled, the pose read at the camera stamp (the recorded pose is 35-83 ms stale). With perfect ego-motion an ego-frame grid re-warped bilinearly at 20 Hz keeps only 0.37-0.57 of a sock's cost and nearest-neighbour warps freeze it in place. Cells outside the view hold until re-observed or past x < -0.4 m: a sock in the track is last seen ~0.65-0.70 m from the mast and the blind travel to the body front takes 0.73 s median / 2.33 s p95, by which time a 0.5 s half-life would leave ~5 %.
Selection and veto: each hypothesis' swept footprint over 1.5 s is checked: non-traversable -> vetoed; `unknown` or within 0.15 m -> v <= 0.15 m/s; all vetoed -> stop, then a bounded recovery (rotate-in-place scan +-60 deg at 0.5 rad/s on the gyro, re-plan, after two scans ask the VLM, then the user; never reverse; logged as an intervention).
Acceptance, two sets. Static (unarmed): sock, flat T-shirt, doll, USB cable, shoe and a 10 cm box on >= 3 carpets plus hard floor, three lightings, 0.4-1.5 m in 10 cm steps (taped), ~1,000 placements with hand polygons at native 1280x800; reported as hypotheses: per-class recall at <= 1.2 m (target >= 90 %), p95 clean-frame false non-floor area (target < 25 cm^2), near-edge error (<= 5 cm at <= 0.8 m), carpet and dark subsets separate. Driven (teleop, policy unarmed, >= 30 approaches): the held cell under the body front at contact scored against the tape, >= 0.7 in >= 95 %.

## 6. Goal conditioning, place graph and the VLM
`place_edges` (the A->B traversal counters behind `/places/graph`) has unit tests but has never been exercised on the robot (user, 2026-10-23): its writers were the removed route follower and trips, and the only remaining writer is `POST /places/{from}/edges/{to}`. Nothing in v1 depends on it.
v1 (weeks 6-7) is intent-conditioned only: the scalar token's intent one-hot {keep, left, right, stop, turn-around} comes from the operator (app) or, at a decision point, from the 27B; the goal image is masked. That covers the straight-lane, planted-clutter, doorway and staircase sub-stages, and it is the control arm of the K4 goal-sensitivity experiment.
v1.5 (weeks 8-10) adds goal keyframes built from the recordings, not from the graph. Along every session, recognition on the far frames (the same DINOv3 CLS match `/whereami` uses) marks the ticks where a confirmed place is recognised; the frames between two recognitions are that A->B edge's keyframe track, stored in a new `edge_keyframes` table keyed by the place pair with each keyframe's CLS and a re-embeddable 416x256 thumb (the CLS changes with every PathNet retrain, so the thumb is the durable record). The subgoal is the next keyframe on the track best matching the current far frame (cosine on the L2-normalised CLS); advance when the distance head reads < 1 s for 3 ticks or recognition hits; "weak" = best cosine < 0.70 or margin < 0.05. Offline measurement, possible today on the six sessions: top-1 within 1.5 m of the true arclength in >= 90 %, false and missed advances < 1 per 20 m each. Building the tracks is also the first real test of the place graph: an edge exists only where a track exists, the hindsight pipeline calls `record_traversal` once per track, and Dijkstra over `place_edges` (recover `places/planner.py`) enters only after `/places/graph` has been read back on the robot with exactly the edges the tracks imply.
"Go to the kitchen" -> places service (:9095) lookup; miss -> one text-only 27B call; still none -> ask.
VLM (the 27B over Edge-LLM, through `bebop_vision/vlm.py`, the OpenAI-compatible client the place importer's name suggestions use) at decision points only: text-to-place; junction nodes with a weak match for 3 s; stuck; hypothesis disagreement; in v1 also the intent source when the operator has not set one.

## 7. The follower
Pure pursuit with pose prediction and curvature-regulated speed, 50 Hz, watchdog 500 ms. Sources: v_odom from `WheelState.velocity_rad_s` (r = 0.0855 m) at the 30 Hz telemetry subscription, not differenced 15.5 Hz odometry; pose from `odom_x/odom_y`, stamped at arrival (R: `DriveState` has no timestamp); heading from the near gyro tap (`OrbbecCamera.add_imu_tap`, 200 Hz); `odom_theta` never.
Parameters: t_pred = 0.075 + 0.30 = 0.375 s with held (v_odom, omega_gyro); L = clamp(v_c x 1.0 s, 0.25, 0.6) m; omega_c = 2 v_c sin(alpha)/L; v_c = min(v_plan(0.15 s), 0.8 omega_max/|kappa_pred|, approach limit, grid cap, 0.3 m/s in v1); |alpha| > 45 deg -> rotate in place at 0.7 rad/s on the gyro (this rule, not pure pursuit, governs sharp corners).
Yaw closure: firmware wz is open-loop kinematics; the in-place carpet gain was ~0.5 and the moving odom/gyro ratio 1.05-1.13, so the moving gain is re-fitted on the 3 m lane first. Trim while moving: omega_sent = omega_c + k_i integral(omega_c - omega_gyro), k_i = 1.5 s^-1, output and integral clamped +-0.3 rad/s, referenced to the instantaneous command.
Stop: v_plan(t_a) < 0.05 and v_plan(t_a + 1 s) < 0.05, or stop logit > 0.5 -> ramp 0.3 -> 0 in 0.6 s. Stale plan: > 0.3 s scale v to zero by 0.6 s; > 0.6 s zeros, re-engage after 3 valid plans.
Transport contract. (R) `RobotClient` queues twists in a 64-deep `asyncio.Queue`, `send_twist` returns True once the put is scheduled, overflow drops the twist without telling the caller (asyncio only prints a `QueueFull` traceback) and `ack` replies are ignored, so under backpressure the firmware would get up to 1.28 s of stale non-zero twists with the zero last. Contract: a latest-wins slot for twists; every twist carries a `request_id` with t_send logged and the Ack matched; no Ack within 200 ms, telemetry_hz < 10 or disconnected -> HOLD; an Error reply to a twist is a preemption event delivered by callback. Bench: send->Ack p99 <= 40 ms over 10 min at 50 Hz; under `netem delay 300ms` the follower enters HOLD within 0.5 s with 0 stale non-zero twists delivered. (Since `9d93ac4` an accepted twist gets no reply; see the repo changes at the top.)

## 8. Safety envelope
States OFF -> SHADOW -> ARMED -> HOLD; SHADOW and OFF never call `send_twist`. The go is an app action, never a voice tool: `POST :9092/nav/go {session_id, max_s: 120, max_m: 15, checklist: {unplugged, wheels_on_floor, operator_present}}` returns 409 unless every checklist bit is true, the firmware is in DialIn with all wheels armed and E-STOP clear, `has_active_operator` is false, the gyro tap and odometry are live and the engine is warm.
HOLD never streams zeros. (R, firmware of 2026-10-23; changed by `9d93ac4` and `a7d3a33`, see the repo changes at the top) `drive_command` writes a zero twist from any connection straight to `cmd_vel`, bypassing arbitration, so a follower streaming zeros at 50 Hz would overwrite a human's teleop twist every 20 ms while parked on a doll. A stop is a bounded burst: 30 zeros at 50 Hz (0.6 s, longer than the 500 ms `operator_timeout_ms` plus one wheel slew) on every transition into HOLD, stop decision or rejected twist; then silence until ARMED again. Bench: policy in HOLD for 60 s while the app teleops; `DriveState.cmd_linear_x` follows the human within 50 ms and never returns to zero without a human stop.
Firmware facts (M: `supervisor.rs::drive_command`, arbitration from 43ab259, before `9d93ac4` and `a7d3a33`; `operator_grace_ms` 2000, tick 10 ms). While the policy's connection sends non-zero twists more often than every 2 s, another connection's non-zero twist is refused and never reaches `cmd_vel`; the client gets an Error reply and `you_are_active_operator=false`, but the firmware logs nothing. A human can still halt with a zero twist, take the seat whenever the policy has commanded zero for > 2 s (a rejected twist sends the follower to HOLD), or release it with E-STOP or mode->Idle; steering takeover during streaming is impossible today. Change (one CI-built PR): `SetVelocityCommand` gains `bool autonomy = 3`; a human's non-zero twist preempts an autonomy holder inside the WS handler and the preempted client stays rejected until the human releases + grace; `autonomy_max_linear_m_s: 0.35` and `autonomy_max_angular_rad_s: 1.0` clamp flagged twists (R: today the only limit is wheel `vel_max: 20.0` rad/s, 1.71 m/s); `DriveState` gains `cmd_source`; an unsolicited `OperatorPreempted`; rejected and preempted twists logged. Both preemption and E-STOP ride the WebSocket; a link-independent stop is a stated gap.
Depth reflex (tall and drop), 10 Hz, both cameras, on the frame after the temporal filter and before hole fill (one extra copy in `orbbec.py`; both streams recorded; operator video keeps [temporal, hole]): RANSAC plane per frame (the YAML plane alone raises 12.8 points per clean frame); tall = a connected cluster of >= 4 stride-4 samples 0.10-1.45 m above the plane (the mast is 1.32 m) persisting 2 of 3 frames; drop = >= 40 px of returns >= 8 cm below the plane, or missing returns, 0.4-1.2 m ahead for 2 of 3 frames -> stop (the staircase). Gate: >= 15 min of clean-floor driving with both streams recorded, replayed offline, 0 stops.
Stall detector, 10 Hz in the reflex thread, because "< 0.3 m in 10 s" notices a pushed doll 10 s late: (a) commanded v >= 0.10 m/s for 0.5 s with far-camera phase-correlation shift < 1 px and |omega_gyro| < 2 deg/s; (b) |omega_sent| >= 0.3 rad/s for 0.5 s with |omega_gyro| < 2 deg/s; (c) per-wheel tracking error (R: `WheelState.velocity_rad_s` vs `target_velocity_rad_s`) > 30 % for 0.5 s while (a) or (b) holds; (d) odom rate vs visual flow mismatch > 2x for 1 s. Any -> stop burst, HOLD, `reason = contact`.
Stop geometry: no fixed polygon. Replayed over the six sessions (M, 6,298 frames): the isotropic footprint + 0.30 m box fires on 17/17 doorway-like passes and 63-65 % of all moving frames; a 0.06 m-lateral polygon long enough to stop 0.2 m before a box fires on 13-18 of 17-18 passes, because `ego_mask.npz` is ~4 cm generous per side and the corpus door is 0.59-0.68 m at jamb height. So the guard is the selected path's swept footprint at the physical body width, lateral margin 0.06 m tapering to 0 between jambs, longitudinal = the stopping distance, the 0.2 m standoff supplied by held cells. Gate: 0 false stops on the 17 passes replayed with the planner's path.
Illumination: log exposure, gain and the near crop's mean luma; luma < 40/255 or exposure at the SDK maximum -> v <= 0.15 m/s, luma < 25 -> HOLD (`reason = dark`); the IR stream is deferred past v1.
Gates: plausibility (|kappa| <= 4 /m, v <= 0.5, monotone arclength, no NaN); plan-to-plan lateral difference at 1 s > 0.2 m for 3 ticks -> v <= 0.15; model failure (exception, NaN, stale > 0.6 s, frame drop > 20 %, latency > 150 ms x5) -> burst, HOLD; rejected twist -> HOLD; no progress (< 0.3 m in 10 s) -> the section 5 recovery.

## 10. Staged plan
Path-head gate (M, constant-velocity baselines, 5,734 two-second windows): holding the commanded twist gives ADE@2 s p50 0.053 m, mean 0.087 m, p90 0.22 m; the odom velocity through the fitted lag 0.059 m p50; the odom finite difference 0.089 m; 81 % of windows are already <= 0.15 m, so the absolute gate is dropped. The gate is relative: mean ADE@2 s and the p90 on turn-onset windows both >= 30 % below both baselines on held-out folds; ego-state-only regressors are already 26-40 % worse than the command-hold baseline on session-held-out folds, so the outcome is unknown.
Week 1, measure: K0-K3; IMU export, fused heading with the stuck/slip flag, label census and previews; the recorder-stall fix; the static clutter set; the firmware preemption/cap PR; the drivable-vs-avoid list signed; `--conf` plumbed into SAM (done 2026-10-23; the default stays 0.5, so labels do not change until a lower value is chosen). Weeks 2-3, traversability + path v0 on 6-fold session rotation (report the spread; nothing passes or fails on this corpus): footprint recall >= 0.95 at FPR <= 0.05; static-set numbers against the section 5 hypotheses; both CV baselines; engine median <= 20 ms, p99 <= 60 ms; power delta <= 6 W.
Week 5, retrain on the full corpus (both CV gates on held-out folds; recovery on recorded recovery starts; planted-doll clearance-only and stop-only rates in replay; driven taped approaches, held cell >= 0.7 in >= 95 %); the action head trained alongside; a 30-minute SHADOW soak during teleop: `send_twist` asserted never called, would-have-vetoed ticks <= 2 % on collision-free driving, reflex would-stop and stall events 0, follower period p99 <= 40 ms.
Weeks 6-7, live, an explicit go per sub-stage, <= 0.3 m/s: 3 m straight x10 (lateral <= 0.10 m, 0 reflex stops; gyro yaw rate logged against omega_sent to re-fit the moving gain); planted sock/doll/shirt x20 (clearance >= 0.10 m or stop in >= 18/20, 0 contacts); one doorway x10 each way (>= 9 clean); the staircase hallway x5.
Weeks 8-10, graph legs (prerequisite: edge tracks built from the recordings and `/places/graph` read back on the robot with the edges the tracks imply; `place_edges` is otherwise untested): 3 places, 20 trips, >= 16 operator-confirmed arrivals, <= 1 intervention per 50 m, <= 1 VLM call per junction; the guarded relabel loop starts; the action head is compared with pure pursuit on the 3 m lane and one doorway and replaces the follower only if not worse on lateral error, overshoot and interventions.

## 11. Risks, kill experiments, open questions
Kill experiments, none of which drive. K0 (1 day) rig pitch: per-session fits spreading > 1 deg on the same floor -> a per-frame gravity-residual pitch input to the lift. K1 (2 days) Thor budget: the untrained graph at the section 3 shapes, trtexec --fp16 median/p99, then inside `main.py` under the full section 2 load for >= 10 min with tegrastats on and off, then 2 min of looped 3-image brain queries; median > 30 ms, > 8 W or any tick past the 500 ms watchdog -> shrink far/goal inputs, then rate, never the near crop. K2 (2 days; partial result in section 4) SAM 3.1 on >= 30 instances per class, including floor-coloured socks and shirts; < 90 % with a hole or a >= 50 % mask -> hand masks + copy-paste are the negative source, +1 week. K3 (1 day) taped course with an independent reference: a 90 deg carpet turn plus >= 1.5 m straight inside 3 s and a separate 3 m straight, >= 10 repetitions each, one deliberate wheel-spin; gyro+odom end point > 10 cm off the tape at 3 s kills hindsight labels. K4 (week 3) goal sensitivity, pre-registered: windows anchored 1.0 s before turn onset, left-vs-right junctions only, scored on the 4 s heading over >= 40 junction events with Clopper-Pearson CIs; < 60 % -> the image goal is a tie-break only. K6 (bench, week 5): the HOLD-teleop, netem and preemption cases must all pass before any live sub-stage.
Accepted risks: memorisation of one evening until the corpus exists; patterned rugs and shadows as the first live false non-floor; odom distance slip while blocked (flagged, not corrected); open-loop ADE correlates weakly with closed-loop success, so interventions per 100 m are the real gate; cross-session generalisation, not fit, is the hard part.
Open questions: whether the untested `place_edges` graph survives its first population from edge tracks; the cause of the recorder stalls; nvjpeg on the Thor; chassis pitch under braking; odom distance scale on carpet (inconclusive so far); the 193619 raised patch on bare carpet.

## 12. What NOT to build, and why
- No SLAM or global metric map for navigation: the grid is F-anchored but ego-bounded, places are topological. The live SLAM proof of concept was removed on 2026-10-24 (`git log -- bebop-vision/bebop_vision/slam`).
- No learned simulator or world model: recovery comes from exact floor-plane warps as augmentation and from recorded recovery starts as the test.
- No foundation policy on the tick: GR00T N1.7-3B is an estimated 25-45 W at 5 Hz with a ~2.7 px sock.
- No 20 Hz before tegrastats earns it, no 100 Hz loop, no MPPI in v1; no previous plan as input; no depth image into the policy.
- No fixed-margin stop polygon of any width: the replay kills both the isotropic and the 0.06 m box; the guard is path-swept with grid memory.
- No zero-streaming stop and no unbounded twist queue: a stop is a 0.6 s burst, the client a latest-wins slot with Acks.
- No runtime trajectory-library scorer; the runtime fallback is the guard.
- The archived `navd_traj` (twist chunks, last-twist input, never driven) is not a base; its differentiable drivability cost is the one idea kept.
- The removed bearing controller, stop-cone, route teach, object seeker and trips are not restored as a stack; recovered from `1f22b61^` is estimation, safety and plumbing only (`nav/pose.py`, `nav/depth_cone.py`'s geometry, `nav/drive.py`'s arming, `places/planner.py`). A tracking controller under a learned planner is the planner/controller split, not the rules engine the user removed.

The robot checkout was then still `3ee5e3f` plus scp leftovers, so the pull was a separate step. (R) `bebop-vision.service` runs `main.py --record-navd ... $BEBOP_VISION_EXTRA_ARGS` with `Restart=on-failure`; the current parser has neither `--nav` nor any `--bev*`/`--no-bev` flag (and, since 2026-10-24, none of `--live-slam*`, `--place-router`, `--router-interval`, `--router-cooldown`, `--router-voice-url`), argparse exits 2 on an unknown flag and `Restart=on-failure` turns that into a 3 s restart loop, which is why the env file is edited before the pull. Write the env file via `sudo -v` then `sudo -n bash -c 'cat > ...'` (piping into `sudo -S tee` writes an empty file). (2) `pgrep -af 'record-nav[d]|main.p[y]'`, never restart mid-session; `systemctl stop bebop-vision`, `git pull`, `systemctl start bebop-vision`; verify with `pgrep`, `journalctl` and a `/snapshot` curl. (3) The service is behind `--path-policy` (default off), so the first deploy changes nothing at runtime. (4) Engines are built on the Thor (`trtexec --fp16`, TensorRT 10.16.2, sm_110; an RTX 5090 engine does not deserialize) with parity against onnxruntime-gpu. (5) The proto change regenerates the three binding sets (Rust prost, app TS, the checked-in Python pb2) and the firmware ships through CI and `install-jetson.sh --linux-only --run-id <id>` with the recorder stopped. (6) Raise the `bebop-models` `tracked` entry `vision` (6 GB today) by the measured engine. (7) Rollback: the previous tag and CI run id together with a `vision.env` line that checkout accepts; the `vision.env.bak-<stamp>` files on the robot carry flags (`--bev-model`, `--nav`, `--no-bev`) that only older checkouts parse, so never restore one blindly.
